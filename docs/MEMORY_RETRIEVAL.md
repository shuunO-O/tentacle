# 记忆检索与原文证据

事件检索移植自 dsh-neo4j-memory 的通用检索算法，沿用 Tentacle 的共享 Ladybug Database、embedding 客户端和概念审计。

`memory_database_search` 默认 `operation=search`。事件查询分别从摘要、原文分块召回最多40个不同事件，先应用实体、创建日期、来源会话和已交付ID过滤，再进行精确余弦排序。两路排名经 RRF（k=60）融合、关键词覆盖补分、完整原文去重和 MMR（lambda=0.85）选择。默认返回8条详细结果，另附最多24条候选索引（ID、短摘要及来源元数据）。索引不计入已交付历史或追查链，可按需read；实际数量受召回和去重影响。分数是检索启发式，不是事实置信度。

详细结果和候选索引均返回 `create_time`（保存时间，不是事件发生时间）及 `raw_session`（来源会话ID）；旧记忆缺失的字段省略。Event search 可传 `session_id` 精确过滤 `raw_session`，可单独使用或与关键词、实体及日期组合；不传则跨来源会话检索。此参数不改变宿主会话的去重归属，且不支持 Person/Concept。

```json
{"session_id":"source-session-id","query_text":"之前讨论的方案"}
```

配置页“记忆检索”可选择返回全文或摘录、详细结果数及是否附带候选索引；对应用户覆盖如下（修改后重启生效）：

```yaml
memory:
  search:
    event_top_k: 8        # 1..20；Person/Concept仍使用原top_k
    content_mode: excerpt # excerpt / full
    include_index: true
    index_top_k: 24       # 0..64
```

摘录模式提供原摘要、每条最多120个Unicode码点的精确原文摘录（整包预算1000字符）、共享概念组和可追查入口。优先从向量命中的原文分块选择摘录，即使命中位置在32000字符之后；缺少有效命中块时在前32000字符中按关键词选取。全文模式返回完整原文，不受摘录预算或前32000字符窗口限制，也不以重复摘录引用替代正文；长记忆会增加上下文用量。每条有原文的详细结果均提供具体read参数。摘要需要原文核实；共享概念不证明因果或发生顺序。完整正文可分页读取：

```json
{"operation":"read","event_id":"event_12","start":0,"limit":1600}
```

分页`read`不需要查询向量或模型Key，limit为1–10000，范围起点包含、终点不包含，与 Python 切片的 Unicode 码点一致。当前会话已交付的event_12可简写为`12`或`Event:12`；其他事件须用完整ID。

```json
{"operation":"read","event_id":"event_12","query_text":"这段记忆中的任职时长","top_k":4,"limit":3000}
```

语义read复用embedding客户端，仅检索指定Event的原文向量，召回最多12块并选择前top_k块（1..4，默认4），合并重叠范围后返回精确原文和位置。limit为总字符预算（默认10000，最大10000），不接受start。可选min_score为-1..1的相关性阈值，不是事实置信度；未达阈值不代表不存在答案。缺少兼容原文向量时明确报错，可使用分页read或补建索引。语义read会调用问题embedding，不接云端重排，不消耗新的事件名额。

```json
{"operation":"expand","cursor":"上次返回的cursor","concept_id":"concept_3","limit":3}
```

`expand` 沿概念等价组的全部成员查找补充事件；组内原始 `MENTIONS` 关系保持不变，只接受当前游标提供的概念入口。沿用原问题向量、实体、日期和来源会话范围，不调用新的embedding或规划模型，每条追查链最多20条。limit兼容1–8，实际交付受配置的event_top_k及链剩余额度限制；返回方式沿用配置的全文/摘录选项。

去重记录和游标按宿主提供的session_id隔离，15分钟过期，最多保留32份会话记录及32个游标；每份记录最多640个事件ID和640段摘录。同一会话的搜索串行提交，数据库错误、渲染失败或取消不会占用交付记录。重复摘录引用已交付原文；`read` 始终可以重读。脱离宿主会话直接调用时不保留去重历史和追查游标。

空结果不证明记忆不存在，可能已排除本会话交付过的事件。独立新问题需要重新检索时：

```json
{"query_text":"重新核对之前的问题","reset_seen":true}
```

该参数仅用于 Event search，成功后才清除当前会话的旧记录和旧游标。Person/Concept定向检索沿用完整匹配信息及有上限的关联事件摘要，保留 `date_from`、`date_to`、`time_hint` 和 `event_limit` 的语义。日期始终过滤写入时间，不代表事件实际发生日期。

## 原文索引与旧记忆

新记忆保留完整Event.content，并按800个码点、相邻120个码点重叠生成内部EventSource分块。摘要、实体和原文分块使用同一embedding客户端，事件、关系及分块在同一事务提交。EventSource不显示在用户图谱中。

旧记忆没有分块时仍可通过摘要检索，命中会提示缺少原文向量。升级不会自动读取全库或调用模型补建。确需补齐时，使用原摘要的同一embedding模型和维度，在有相应环境变量的维护环境运行：

```powershell
.\.venv\Scripts\python.exe scripts/memory_sources.py --apply
```

此入口不启动Agent。该脚本需要先关闭宿主，不能与读写数据库同时打开。它先计算所有分块向量，再在数据库事务中核对事件快照并替换来源；使用本地数据库写事务。模型请求失败或快照变化时不替换旧来源。它不改事件ID、原文、摘要、概念或原有向量，也不承担更换embedding模型的全库重新向量化；旧事件未记录模型名时，需要操作者确认与原模型一致。

原文向量召回和沿概念追查适用于日常对话与个人长期记忆检索，无需章节结构。

## 更换 embedding 模型或维度

在应用配置中更新现有「向量嵌入」角色。需要换维度时，在「服务与维护 → 记忆检索」更新向量维度。
保存后点击「重算记忆向量并重启」。应用会等当前对话结束，在重启期间用保存的模型重算，并在配置页显示结果。
全量操作会向所选 embedding 接口提交事件摘要、实体名称和原文切片，产生模型用量。成功后才切换库文件。
失败后可重试，也可改回原模型及维度并重启，以继续使用原向量。

也可停服后使用维护命令。使用应用运行账号和同一套模型环境变量，从项目根运行：

```powershell
.\.venv\Scripts\python.exe scripts/memory_sources.py --reembed-all --apply
```

命令读取当前配置，全部成功后切换 `memory.ladybug.path` 指向的文件。也可以用 `--output` 将结果写到另一个路径。
