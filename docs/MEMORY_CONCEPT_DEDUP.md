# 历史 Concept 去重

与新记忆对齐共用 `concept-retrieval-entry-v2`，
按“是否适合共享一个记忆检索入口”判断；增加自动/人工操作审计及显式重新评估。门槛不变。

入口为侧栏「概念去重」。此功能独立于新记忆写入对齐，不在启动、心跳、scheduler
或 agent 工具注册时执行。打开页面只读取本地审核记录，点击「开始扫描并分组」后才读取
现有 Concept 并调用 Jev。

## 使用

1. 在应用配置中为 `concept_dedup` 绑定 System One 模型，配置主机凭据后重启。
2. 页面设置每个概念候选数（默认 5）和本轮配对上限（默认 200），点击「开始扫描并分组」。
   启动确认明确说明高置信适合共享检索入口的候选会自动分组。
3. 查看进度和累计记录。不确定、模型错误、证据不足、证据变化的记录留在「待审核」。
   两侧展示名称、ID、别名、首次摘要、最近最多三条相关事件摘要，以及模型三档概率。
4. 待审项可以「保持独立」，或选择左/右参考概念后点击「加入同组」。原始关系与属性分别保留。
5. 证据过期可点「刷新证据」再人工决定。刷新后旧概率仅留为历史字段，不继续展示为当前判断。
   分组结果因连接中断未确认时，只允许按上次分组参考概念重试确认，不能改为独立或刷新。
6. 可随时「停止扫描」；当前候选检查完成后停止，已经完成的分组不会撤销。
7. 「重新评估」按当前规则再次调用 Jev，产生模型用量；保存旧语境/判断后更新当前候选，
   不自动分组，结果仍待人工确认。已分组/保持独立或提交结果待确认的配对不能重判。
   「刷新证据」仍只更新图谱证据，不调用模型；再次扫描也不会隐式重判旧候选。

页面支持待审核/已分组/保持独立/判定不同/全部筛选，每页 30 条。
“判定不同”也可以人工改判。已选择独立的配对持续排除，并约束其所在组后续的分组操作。
图谱页面选中概念后可查看等价组成员，点击成员名称可跳转到该节点。
「移出等价组（撤销此概念合并）」将当前概念移到新的独立组，其余成员仍共享原组；
不调用模型，不改写原节点、别名或事件关系。旧追查游标会失效，需重新检索。
本地导入图谱只供查看，不提供此写入操作；请求失败时不会自动重发，需先刷新核对结果。
移出操作单独记入人工审计，历史配对结论保留为操作记录，不隐式改成「保持独立」。
当前版本不提供独立判定撤回或整次多成员分组的一键还原；过去已硬合并的节点和关系无法由此恢复。

## 召回和自动决策

`ConceptMaintenance.page` 分页读取 50 个现有节点，使用现存 embedding 做精确余弦排序，候选按组去重，
并与名称/别名精确候选取并集。不调用 embedding API、不读取会话或图片。
每个无序候选对只检查一次。名称相同也须经过语义判断；大量同名项允许逐对处理，
不使用新记忆对齐的“候选必须完整消歧”限制。

`ConceptDedupManager._inspect` 将两个节点的有限语境交给 `JevClient`，采用检索入口归并三档规则。
适合分组概率 ≥ 0.95 时自动分组；应独立概率 ≥ 0.90 记为不同；其他结果进入人工审核。
可分组严格语义不完全相同但属于同一稳定记忆主题的项目称呼/具体载体；共同出现本身不是充分条件。
自动选择数字序号更早的概念作分组参考（例如 concept_2 优先于 concept_10），两个组的全部成员共享入口。
人工可反向选择参考组；每次分组都单独判断、核验和提交，不推断其他组也应加入。

默认每轮最多 200 对，可调 1～1000；候选数可调 1～20。每轮约 15 分钟处理预算，单次
外部请求/查询沿用原有超时。达到上限会标记 limited，而不是声称全库
已去重；再次人工启动会从头分页，跳过已有配对，继续未处理项。服务重启不会自动重放任务。
缺少/重复 ID 会在启动前拒绝；缺向量和召回异常计入进度异常，不当成“没有相关概念”。
只判断召回范围内的候选，不承诺已找到所有等价概念。

维护模型配置独立于 `memory.concept_alignment.enabled`：

```yaml
memory:
  concept_dedup:
    model_role: concept_dedup
    same_probability: 0.95
    different_probability: 0.90
```

默认 `concept_dedup` 角色使用 OpenRouter 的 `typesafe/jev-1.13`，密钥变量为 `OPENROUTER_API_KEY`。
供应商、模型与角色统一在 Web 配置页管理，角色选择、门槛和超时在「运行与工具 → 记忆去重」调整。
显式 API Key 仍只放环境或 `.env`；页面不接收密钥。
调用用量进入现有 UsageTracker 的 `memory_alignment` 分类。

## 等价概念分组与追溯

`ConceptMaintenance` 在一个 Ladybug 写事务内重新核对概念组成员与关联关系的指纹，
然后把两个组的全部成员归入同一 `equivalence_group`，并写入 `ConceptGroupAudit`。
不删除节点、不改名称或别名、不迁移或折叠关系；关系属性即使互相冲突也分别保留，
所以没有“保留哪一侧属性”的选择。图谱仍显示所有原始节点和关系。

分组后，任一成员名称都可检索整个组的记忆；共享概念数量按组去重，关联事件度数按不同事件计数。
扫描按组选择候选，已经同组的概念不会再次判断。新记忆保存与人工分组共用宿主写锁。
人工选择保持独立的概念仍按原 ID 记录；两个组包含这样的跨组配对时，后续分组会被阻止。

已有审核协议中的 `merge` 动作、`merged` 状态以及 keep/drop 字段继续作为操作标识，实际行为为分组。
operation ID 与结果写入同一个图事务；丢失回执后只允许按原选择确认，不自动重放。
概念组变化会使旧追查游标失效，需要重新检索。

## 持久化和鉴权

审核队列和操作审计继续保存在 chronicle 同目录的 `concept_dedup.db`。
自动评估、人工评估、分组和保持独立分别留痕，图事务与 SQLite 的最终确认仍通过 operation ID 衔接。
服务重启只标记中断，不自动扫描、调用模型或重放图操作。

图谱及审核接口位于 `/api/memory/`，包括 `dedup`、`dedup/audit`、`dedup/start`、`dedup/cancel`，
以及 `dedup/{pair_id}/refresh`、`reevaluate`、`decide`。`POST concepts/detach` 接收
`{"concept_id":"concept_12"}`（也接受 `Concept:concept_12`），执行上述单个概念移出操作。
全部复用密码与设备鉴权。
已安装的客户端可继续使用 `/api/neo4j/` 下的原地址，服务端同样使用 Ladybug。
审计分页每页 30 条，可按自动、人工参与筛选。

本次仅实现 Python Ladybug 存储与分组行为，不包含旧 Neo4j 数据迁移、数据库回退或备份恢复。
